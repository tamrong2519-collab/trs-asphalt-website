# TRS TAMRONGSAK CONSTRUCTION — เว็บไซต์ธุรกิจรับเหมางานผิวทาง

เว็บไซต์ภาษาไทย 4 หน้า ใช้ Vite และ JavaScript ไม่ต้องมีฐานข้อมูลหรือ backend รองรับมือถือ แท็บเล็ต และเดสก์ท็อป

การแสดงผลบนมือถือปัจจุบันใช้การจัดวางแบบคอมพิวเตอร์ทั้ง 4 หน้า ตามที่ผู้ใช้เลือก: HTML ตั้ง `<meta name="viewport" content="width=1280">` เพื่อให้เบราว์เซอร์มือถือย่อทั้งหน้าให้พอดีจอ โลโก้ เมนู Hero การ์ด และ Footer จึงอยู่ตำแหน่งเดียวกับหน้าคอมขนาด 1280px ตัวหนังสือและปุ่มจะเล็กลงตามสัดส่วน และยังใช้สองนิ้วซูมได้โดยไม่มีข้อจำกัดจากเว็บไซต์ ส่วนคอมพิวเตอร์ใช้ความกว้างหน้าต่างตามปกติ

ทดสอบพฤติกรรมนี้ด้วย mobile emulation ที่เปิด `isMobile: true` และ `hasTouch: true` ที่ 320, 375, 390 และ 430px ใน `tests/mobile-desktop-layout.spec.js` การทดสอบเดิมที่ตั้งเฉพาะความกว้างหน้าต่างยังตรวจ CSS Responsive ของเบราว์เซอร์คอมพิวเตอร์ หากต้องการกลับไปใช้การเรียงคอลัมน์สำหรับมือถือ ให้คืน viewport ใน HTML ทั้ง 4 ไฟล์เป็น `width=device-width, initial-scale=1.0` รายละเอียด Responsive ด้านล่างอธิบาย CSS ที่ยังเก็บไว้สำหรับการแสดงผลแบบนั้น

## เปิดเว็บไซต์เพื่อพัฒนา / Preview

ใช้ Node.js 20.19+ หรือ 22.12+ (สภาพแวดล้อมนี้ใช้ Node.js 24)

```bash
cd /workspace/trs-asphalt-website
npm ci --cache /tmp/trs-npm-cache
npm run dev -- --port 5173
```

เซิร์ฟเวอร์รับการเชื่อมต่อบน `0.0.0.0:5173` หากเครื่องมือที่ใช้มี Preview หรือ Ports ให้เปิดพอร์ต 5173 ถ้ารันบนคอมพิวเตอร์ของคุณ เปิด `http://localhost:5173` ได้

ตรวจ production:

```bash
npm run build
npm run preview -- --port 4173
```

ไฟล์สำหรับนำไปเผยแพร่เป็น static hosting อยู่ใน `dist/` ต้องเผยแพร่ทั้งโฟลเดอร์ รองรับ URL `/index.html`, `/services.html`, `/projects.html`, `/contact.html` โดยไม่ต้องตั้ง SPA fallback

## แก้ข้อมูลก่อนเผยแพร่จริง

- `src/data.js`: ชื่อธุรกิจ เบอร์โทร LINE อีเมล ที่อยู่ พื้นที่ให้บริการ เวลาทำการ และ URL เว็บไซต์จริง
- ข้อมูลติดต่อได้รับการยืนยัน: โทร 062-248-4089, LINE @138wlldt, อีเมล tamrong2519@gmail.com
- `src/main.js`: ข้อความส่วนหน้าแรกและเนื้อหาหน้าต่าง ๆ
- `src/style.css`: สี ขนาดตัวอักษร และการจัดหน้า
- `public/images/`: ใส่ภาพหน้างานจริง แนะนำ WebP/AVIF ที่บีบอัดแล้ว ความกว้างประมาณ 1200px
- ชื่อ SEO และ description ใน HTML ทั้ง 4 ไฟล์ควรปรับให้ตรงชื่อธุรกิจและพื้นที่ให้บริการจริงด้วย

### เพิ่มผลงานหลายรูป

เพิ่มข้อมูลใน `projects` ของ `src/data.js` เช่น:

```js
export const projects = [{
  title: 'ชื่อโครงการจริง',
  category: 'asphalt', // asphalt / gravel / speed-bump / marking
  location: 'พื้นที่โครงการ',
  description: 'รายละเอียดงานจริง',
  images: [
    { src: '/images/project-01.webp', alt: 'รายละเอียดภาพหน้างานรูปแรก' },
    { src: '/images/project-02.webp', alt: 'รายละเอียดภาพหน้างานรูปที่สอง' },
  ],
}];
```

ผลงานกรองตามประเภทและเปิดภาพใหญ่ได้ ภาพ hero.webp และ work-scenes.webp สร้างขึ้นใหม่เป็นภาพประกอบ ไม่ใช่ภาพผลงานจริง รูป Reference ไม่ได้ถูกนำมาใช้เป็นภาพบนเว็บไซต์ โลโก้ SVG วาดขึ้นใหม่ตามแนวทางแบรนด์

## การขอประเมินราคา

ฟอร์มตรวจข้อมูลจำเป็นแล้วสร้างข้อความในเครื่องของผู้ใช้ ให้คัดลอกข้อความ เปิด LINE หรือส่งผ่านแอปอีเมล (เมื่อกำหนดช่องทางแล้ว) ไม่มีการส่งอัตโนมัติ ไม่มีการบันทึกข้อมูลบนเซิร์ฟเวอร์ หากต้องการรับข้อมูลผ่านเว็บไซต์โดยตรง ต้องเชื่อมต่อ backend หรือผู้ให้บริการฟอร์มเพิ่มเติม

## SEO และความเร็ว

Build จะสร้างเนื้อหา HTML ทั้ง 4 หน้าให้อ่านได้โดยไม่ใช้ JavaScript มี title, description, Open Graph, semantic headings และฟอนต์ไทยที่เสิร์ฟจากเว็บไซต์เอง เมื่อกำหนด `siteUrl` จะสร้าง canonical, structured data, sitemap.xml และ robots.txt ที่อ้างอิงโดเมนจริง หลังแก้ข้อมูลให้ build ใหม่เสมอ ไม่รับประกันอันดับ Google

## ดีไซน์ตาม Reference

ใช้โทนขาว น้ำเงินเข้ม และฟ้าสด Header พร้อมเบอร์โทร Hero ภาพเต็มความกว้าง การ์ดบริการ 5 ประเภท (แยกหินคลุกกับหินเกล็ด) แกลเลอรี 3+2 บนเดสก์ท็อป หน้าติดต่อแบบภาพคู่ข้อมูล ปุ่มลอยโทร/LINE และ Footer ลายเฉียงฟ้า รองรับหน้าจอ 320px ขึ้นไป ภาพตัวอย่างถูกบีบอัดเป็น WebP และใช้ซ้ำเพื่อประหยัดการโหลด

### การอ่านและแตะบนมือถือ

ข้อความทั่วไปบนมือถือ 16px ขึ้นไป Hero 34–44px พร้อมคำอธิบาย 19–20px การ์ดเรียงคอลัมน์เดียว ปุ่มหลักสูง 56px หน้าติดต่อใช้ปุ่มโทรสีน้ำเงินเข้มและ LINE สีเขียววางซ้อนกัน ขอบมน 16px ตัวอักษร 17–18px ปุ่มลอยถูกซ่อนเฉพาะหน้าติดต่อบนมือถือเพื่อไม่ให้ซ้ำกัน การทดสอบตรวจขนาดตัวอักษร ปุ่มไม่ตัดข้อความ ระยะขอบ และหน้าจอไม่ล้น

### สไลด์หน้าแรกแบบพรีเมียม

Hero หน้าแรกใช้ภาพเต็มความกว้าง เงาน้ำเงินเข้ม หัวข้อ Noto Sans Thai ขาว–ฟ้า และปุ่มขอประเมินราคาฟรี สไลด์ 5 ภาพเปลี่ยนอัตโนมัติทุก 6 วินาทีด้วย Crossfade 750ms มีลูกศร เลขสไลด์ และปุ่มพัก โดยไม่มีจุดบอกตำแหน่ง รองรับการปัดบนมือถือ หยุดเมื่อกำลังใช้งานหรือเปิดหน้าอื่น ผู้ใช้ที่ตั้งลดการเคลื่อนไหวจะเริ่มแบบพักและไม่มีเอฟเฟกต์ ส่วนอื่นของเว็บไซต์ใช้ดีไซน์เดิม

### หัวเว็บ

Header พื้นขาวตาม Reference ล่าสุด พร้อมโลโก้เดิม เส้นคั่นบาง และชื่อ TRS / TAMRONGSAK / CONSTRUCTION เรียงสามบรรทัด เมนูชื่อเต็มทั้ง 4 หน้าแสดงหน้าปัจจุบันด้วยเส้นใต้ฟ้า ปุ่มโทรสีฟ้าทรงแคปซูลและ LINE สีเขียวขอบมนแสดงครบทุกขนาดจอ มือถือใช้แบรนด์กับปุ่มเมนูแถวบน และปุ่มโทร/LINE สูง 52px ตัวอักษร 16px ในแถวถัดมา Header ตรึงด้านบน เมนูปิดด้วย Escape หรือคลิกนอกแผงได้

### ฟอนต์และน้ำหนักตัวอักษร

ใช้ Noto Sans Thai แบบเสิร์ฟจากเว็บไซต์เองทั้ง 4 หน้า ข้อความทั่วไปน้ำหนัก 400 เมนูและปุ่ม 500 หัวข้อการ์ด 600 หัวข้อหลักและหัวข้อส่วนต่าง ๆ 700 คำอธิบายและช่องกรอกข้อมูลมีขนาดอย่างน้อย 16px ระยะห่างบรรทัด 1.65–1.8 และจัดคำไทยโดยไม่เพิ่มระยะระหว่างตัวอักษร ปรับรูปแบบรวมได้ใน `src/typography.css` ส่วนปุ่มโทรและ LINE ขนาดเล็กใน Header คงขนาดล่าสุด

### หน้าแรกตาม Reference ล่าสุด

หน้าแรกใช้ Header โลโก้พร้อมเมนูและปุ่มโทรสีฟ้า Hero สัดส่วนประมาณ 2.64:1 บนคอมพิวเตอร์ หัวข้อขาว–ฟ้า ลูกศรด้านข้างและปุ่มประเมินหน้างานฟรี โดยเอาจุดบอกตำแหน่งสไลด์ออก แถบจุดเด่น 3 ข้อ การ์ดบริการ 5 ใบ ผลงานแบบ 3+2 และ Footer ขาวพร้อมลายเฉียง ใช้รูปหน้างานเดิมและ Noto Sans Thai ส่วนหน้าอื่นคงเดิม ปรับได้ใน `src/home-reference.css` มือถือเรียงการ์ดคอลัมน์เดียว ข้อความทั่วไป 16px ขึ้นไป และปุ่มแตะได้สะดวก

### รูปผลงานหน้าแรก

การ์ดผลงานทั้ง 5 ใบมีขนาดเท่ากัน ใช้ภาพสัดส่วน 16:10 และครอปโดยรักษาสัดส่วนภาพ บนคอมพิวเตอร์จัด 3 ใบแถวแรกและ 2 ใบกึ่งกลางแถวล่าง แท็บเล็ตใช้ 2 คอลัมน์พร้อมใบสุดท้ายกึ่งกลาง มือถือเรียงคอลัมน์เดียว เปลี่ยนภาพได้ใน `src/data.js` และปรับการจัดวางใน `src/home-reference.css`

กรอบรูปบริการ รูปผลงาน รูปติดต่อ และภาพขยายทั้ง 4 หน้าใช้สี่เหลี่ยมมุมมน 16px ปรับมุมมนร่วมกันได้ที่ `--photo-radius` ใน `src/photo-frames.css` ส่วนภาพด้านบนสุดและสไลด์ใช้มุมเหลี่ยมเต็มความกว้างเหมือนเดิม

### ลูกศร

ใช้ SVG เส้นบางที่กำหนดใน `src/main.js` และจัดรูปแบบใน `src/arrows.css` การ์ดใช้หัวลูกศรสีฟ้า ปุ่มใช้ลูกศรตรง สไลด์ใช้หัวลูกศรสีขาว บนคอมพิวเตอร์มีการเลื่อนลูกศร 3px เมื่อชี้เมาส์ บนมือถือปุ่มเลื่อนสไลด์อยู่ด้านล่างและมีพื้นที่กดอย่างน้อย 44×44px รองรับการตั้งค่าลดการเคลื่อนไหว

### Hero ขาว–ฟ้าและปุ่มโทรสีฟ้า

Hero หน้าแรกใช้ข้อความตามภาพล่าสุด: “รับเหมาลาดยางมะตอย และงานหินคลุกครบวงจร” พร้อมคำอธิบาย 3 บรรทัด จุดเด่น 4 ข้อ ปุ่มสีฟ้า “โทร 062-248-4089” ที่กดโทรได้ทันที และข้อความประเมินเบื้องต้นฟรี รูปแบบอยู่ใน `src/hero-estimate.css` ภาพ `hero-sharp.webp` เป็นภาพประกอบที่ปรับใหม่ให้เครื่องจักรใหญ่ขึ้นและรายละเอียดพื้นถนนคมชัด ลดการบีบอัดไฟล์ภาพด้วย WebP คุณภาพ 96 และใช้ `hero-sharp-mobile.webp` ขนาด 960×640px สำหรับจอเล็กผ่าน `srcset` บนคอมพิวเตอร์จำกัดเงาขาวไว้ด้านข้อความและปล่อยภาพด้านขวาให้เห็นสีจริง บนมือถือแสดงภาพสูง 230–290px เหนือข้อความโดยไม่มีเงาขาวทับภาพ เพื่อให้เห็นเครื่องจักรและภาพหน้างานชัดเจนทั้ง 5 สไลด์ ตัวควบคุมสไลด์อยู่ขอบล่างของภาพบนมือถือเพื่อหลีกเลี่ยงการทับกับปุ่มโทรและ LINE ที่ลอยด้านล่าง สไลด์ยังเปลี่ยนอัตโนมัติ 5 ภาพ โดยจองพื้นที่ข้อความให้ความสูงคงที่บนมือถือ


### เมนูตาม Reference

เมนูใช้ชื่อเต็มทั้ง 4 หน้าเป็นลิงก์ข้อความแนวนอนพร้อมเส้นใต้ฟ้า และแสดงทันทีทุกขนาดหน้าจอ รูปแบบอยู่ใน `src/navigation.css` บนคอมพิวเตอร์จัดหัวเว็บแถวเดียว บนแท็บเล็ตแยกเมนูไว้แถวที่สอง และบนมือถือเรียงโลโก้ เมนู และช่องทางติดต่อเป็นสามแถว รองรับคีย์บอร์ดและการตั้งค่าลดการเคลื่อนไหว โครงสร้าง Header อยู่ใน `src/main.js` โดย `headerBrand` ใช้เฉพาะหัวเว็บ ส่วน Footer ใช้รูปแบบเดิม ปุ่มโทรและ LINE ใน Header กว้างเท่ากัน สูง 40px ใช้กรอบแคปซูลและมุมโค้งเหมือนกันทั้งคู่ ไอคอนขนาด 16–18px มีพื้นที่แตะสูง 44px และย่อขนาดตามหน้าจอเพื่อให้ข้อความอยู่บรรทัดเดียว

### การจัดตัวอักษรหน้าแรก

คงฟอนต์ Noto Sans Thai และข้อความ Hero เดิม แบ่งหัวข้อเป็นวลีเพื่อไม่ให้คำว่า “มะตอย” หลุดไปอยู่บรรทัดเดียว บนมือถือข้อความรองในหัวข้อมีขนาดเล็กกว่าหัวข้อหลัก คำอธิบายไหลตามความกว้างจอโดยไม่บังคับขึ้นบรรทัดแบบคอมพิวเตอร์ รายละเอียดทุกส่วนของหน้าแรกมีขนาดอย่างน้อย 16px รวมถึงช่วงแท็บเล็ต การ์ดบนคอมพิวเตอร์ใช้ความกว้างเต็มใต้ไอคอน ส่วนบนมือถือจัดคอลัมน์ข้อความให้ขยายเต็มพื้นที่ ปรับได้ใน `src/home-reference.css` และ `src/hero-estimate.css` การทดสอบ `tests/home-typography.spec.js` ตรวจการอ่านและข้อความล้นที่ 320, 375, 390, 430, 768, 853, 1024 และ 1440px พร้อมตรวจความสูงคงที่ครบทั้ง 5 สไลด์

### Footer แบบที่ 5

ส่วนท้ายทั้ง 4 หน้าใช้พื้นขาวอมเทา โลโก้และชื่อบริษัทเรียงสามบรรทัด ข้อความสั้น ปุ่มโทร/LINE ทรงแคปซูลขนาดเท่ากัน เมนูครบ 4 หน้า พื้นที่ให้บริการ และลิขสิทธิ์ พร้อมแถบลายเฉียงฟ้าสูง 8px มือถือเรียงช่องทางติดต่อเต็มความกว้างและเผื่อพื้นที่ให้ปุ่มลอย บนคอมพิวเตอร์ปุ่มลอยจะซ่อนเมื่อ Footer อยู่ในหน้าจอเพื่อไม่ให้ทับข้อมูล ปรับรูปแบบได้ใน `src/footer.css` ข้อมูลติดต่อยังแก้ได้จาก `src/data.js`

การจัดวาง Footer ตรงกับภาพตัวอย่างแบบที่ 5: กรอบมุมมนกว้างสูงสุด 1288px แถวบนใช้ Flex กระจายโลโก้ ข้อความ และปุ่มติดต่อสามส่วน ระยะขอบด้านใน 36px บนคอมและ 22px บนมือถือ เมนูมือถือเรียงและขึ้นแถวตามพื้นที่เหมือนตัวอย่าง พื้นที่เผื่อปุ่มลอยอยู่ด้านนอกกรอบ
